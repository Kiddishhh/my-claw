# Web 团队验收接线复核

本次按当前源码复核，不能将离线测试等同于真实模型/云端验收。

| 能力 | 实际接线 |
| --- | --- |
| 服务器运行主 Agent | dispatcher.run_task → build_agent → ainvoke |
| 子 Agent | build_remote_subagents，共享当前沙箱和指导路由 |
| skills / AGENTS.md | /guidance/ 服务器只读路由，主、子 Agent 显式加载 |
| 子代理串行 | 主图 TaskSerializationMiddleware 对整个 task 持锁 |
| 审计 / Token / 调用上限 | 主、子图各自实例；主计量不代表团队总量 |
| 文件保存 | dispatcher 完成/异常后由应用保存，不是模型主动备份 |
| 恢复 | 明确沙箱 404 + 有效磁盘版本 → 新建上传 → 安装尝试 |
| 依赖异常 | 诊断注入任务，已有工作区不强制重装 |
| 空闲回收 | 持锁、保存成功后回收；用户删除接口未实现 |

复核中补齐了 dispatcher 的 callbacks、主/子模型调用上限和可选 include_state，
让验收走真实入口仍能观察轨迹。默认不返回完整图状态，不改变普通调用的简洁结果。
修正 ToolAudit 对 error ToolMessage 的成功标记；执行命令业务成功仍须检查退出码。

## 新验收脚本

`python -m scripts.verify_web_team`：真实模型 + Daytona，默认只尝试一次。
场景使用 Node 原生测试器，无需 npm 第三方包，避免网络安装影响基础链路判断。
不限制框架在正式业务中的角色选择，仅固定本次验收需求的三角色顺序。

硬性检查：实际委派顺序与返回、主图不写文件/执行、最后 reviewer 的结构化结论、
模型/规则/技能观测、task 区间无重叠、Node 测试与构建退出码、独立行为断言、
磁盘清单哈希、删除后更换沙箱 ID、恢复文件字节一致、恢复后再次通过测试和构建。

参考脚本中的 stdout 包含 passed、tail/tee 管道、任意含 approved 的消息都不足以证明成功。
这里使用直接命令退出码、独立 Node assert，以及 tool_call_id 精确关联 reviewer。
生成代码只在沙箱执行；服务器只验证字节与哈希。报告即使失败也会保留。

## 仍然明确的边界

- 无对话持久化、前端上传/下载/删除接口、持续预览服务管理、浏览器视觉验收。
- 本地备份不是 OS 禁执行区；当前平台不给模型宿主执行工具，不运行下载的代码。
- 工作区保存源码、测试、配置及静态资源；依赖、构建输出和日志不备份，恢复后重新安装和构建。
- 保存期间若后台进程持续写文件，会拒绝发布不一致版本；不是进程或数据库快照。
- 不保证任意 Web 框架/任意镜像都可运行；真实 Node/npm、网络和模型能力需实际运行验收。
